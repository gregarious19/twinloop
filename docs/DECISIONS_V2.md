- D-V2-2 — Two machines: SPARK writes all library code and runs inference/pipeline/app/evaluation; CLUSTER (Slurm, 80 GB GPUs) generates training data and trains. Reason: the owner wants training in one place and the pipeline on the Spark; the Spark GPU is busy with first-pass training.
- D-V2-3 — Strict file ownership per machine (SPEC_V2 §1), separate progress and decision files. Reason: two Claude sessions commit to one repo; disjoint files make every owner `git pull` conflict-free.
- D-V2-4 — The owner does all git pushes and data rsyncs; sessions write `WAITING ON OWNER` lines. Reason: no cross-machine credentials for Claude; keeps data movement visible.

Reason: owner's instruction — the running v1 agent must not see v2 instructions; Track A needs only v1 T02–T04 code.

## Repair loop
- D-V2-14 — `build_graph` keeps up to 8 components (2 main trees + fragments). Reason: a gap splits a vessel; v1 would drop the distal piece silently.
- D-V2-15 — Actions: keep, extend, add, remove, restore, stop. `stop` (likely occlusion) is never filled, only flagged. Reason: filling a true occlusion would hide the most important finding.
- D-V2-16 — Decider = scikit-learn HistGradientBoostingClassifier on 31 hand-made geometry + intensity features, no anatomy features. Reason: fast on CPU, little data, inspectable; anatomy-free means datasets can be made on CLUSTER without TotalSegmentator and the decider works when anatomy fails. An LLM can be added later.
- D-V2-17 — Gap-filler = small 3D U-Net conditioned by cropping (64³ patch, 0.4 mm) + a seed-heatmap channel; may return "nothing found" (< 20 new voxels). Reason: simpler than a general promptable model; location is the only prompt needed.
- D-V2-18 — Training data from deliberately damaged GT masks (gap, truncate, delete branch, shrink, false branch, occlusion with intensity edit), then real failures from `v2_realfail`. Reason: no human correction labels exist; the occlusion and shrink types teach the model to respect true narrowing.
- D-V2-19 — Max 3 repair iterations; decider confidence < 0.6 → flagged for review, no change. Reason: bounded runtime; uncertain cases go to a human.
- D-V2-20 — Repair and lumen refinement are off by default until S16 shows they beat v1 on the regression set. Reason: never ship a change that is not measured to help.

## Lumen and flow
- D-V2-21 — Lumen model = per-slice 2D U-Net encoder/decoder + transformer across ≤ 128 straightened cross-sections (48×48 px, 0.2 mm, every 0.5 mm along the centerline). Reason: compares a narrowing with the segments before and after it, as a reader does on CPR.
- D-V2-22 — Rotation-minimising frame (double reflection) for CPR. Reason: no twisting of cross-sections along curved vessels.
- D-V2-23 — Myocardial-mass flow: q_rest = 1.0 mL/min/g × (myocardium mL × 1.05 g/mL), split between trees by Σ outlet r³; `auto` mode falls back to the v1 diameter law without a valid myocardium. The 1.0 value is verified in S09. Reason: patient-specific flow is the main point of segmenting the myocardium.
- D-V2-24 — FFR uncertainty flag: re-solve with lesion radii ×0.9 and ×1.1; flag if the tree's min FFR crosses 0.80. Reason: segmentation error near the cut-off flips decisions; the report must say so.
- D-V2-25 — No 3D CFD, no VMTK in v2. Reason: unreliable ARM builds; the 1D solver stays.

## Training (details in SPEC_V2 §14)
- D-V2-26 — 3 seeds per network on CLUSTER, deploy the best by validation metric (validation = `v2_train` cases with id % 10 == 3); only the deployed seed is evaluated end to end. Reason: protocol needs ≥ 3 seeds; end-to-end evaluation of all seeds costs too much.
- D-V2-27 — Gap-filler validation metric = Dice of the new voxels only. Reason: copying the input mask already gives a high full-patch Dice.
- D-V2-28 — Models exchanged as files under `models/v2/<name>/` with `config.json` (incl. sklearn/torch versions). Reason: SPARK loads exactly what CLUSTER trained; version mismatches are detectable.

## D-V2-S18 — diagnostics choices (2026-10-26)
Radius method (D2): EDT of the full predicted/GT mask with voxel sampling in mm, no half-voxel term (CenterlineParams.radius_half_voxel_correction is False), read by trilinear interpolation at the GT point; the pipeline computes the EDT per connected component, so values can differ if components touch. Added control column `r_gtmask_at_gt` and `in_predmask` to the points CSV. `same_branch`: each predicted branch is assigned the GT branch that is nearest for the majority of its points; same_branch is True when that equals the GT point's branch (recorded for all points, reported for d ≤ 2 mm). Lesion points: indices inside a `detect_lesions` run of the GT branch. D3 shift: per branch one random unit vector (default_rng(0), branch order of the trees), projected perpendicular to the local tangent (np.gradient) and normalised; the same seed is used for 0.5 and 1.0 mm. ## D-V2-S19 — radius-definition and calibration choices (2026-10-26)
r_ins = the GT branch radius at the point (pipeline/EDT, as in S16/S18); raw EDT read added as `r_edt_at_pt`. r_eq: CPR via `straighten_points` with `V2Params().cpr` (48 px, 0.2 mm, 0.5 mm step) on the GT mask, 8-connected component of the centre pixel (24, 24), area 0 if the centre is outside; `r_eq_nn` (nearest component, the net's trained definition) added as an extra column; per-slice values interpolated onto the branch `s_mm`. `ds_gt` of lesion points = the lesion's ds at its minimum. r_lumen taken at GT lesion minima: same branch/index for GT centerlines, nearest predicted point within 2 mm (stenosis_metrics rule) for predicted centerlines (first-pass tree, no repair). ## D-V2-S20 — area-equivalent radius, stenosis error metric, re-score (2026-10-26)
- **Default change:** `V2Options.radius_mode` defaults to `"area_eq"` (owner decision; the solver depends on lumen area). `v2=None` (v1) is unchanged and inscribed; the CLI and web app use `V2Options()` and therefore area_eq. Repair/lumen defaults unchanged (still False).
- **area_eq_radii** (`src/twinloop/radius.py`): signature is `area_eq_radii(graph, mask, cp=CprParams(), cl=CenterlineParams())`, not `(graph, mask, spacing)`; the grid (spacing/origin/direction) comes from the `sitk.Image` mask, so a separate spacing argument would be redundant. `graph` may be a CoronaryGraph or a list of trees. CPR geometry = `straighten_points` with `CprParams` (48 px, 0.2 mm, 0.5 mm step, rmf frame from central-difference tangents), mask sampled with nearest neighbour; component = `cpr.center_component` (8-connected, containing the centre pixel, else the nearest component = `r_eq_nn` of S19); r = sqrt(A/pi). A slice with no mask pixel keeps the inscribed radius there. Per-slice values are interpolated onto the branch `s_mm`. Smoothing: v1 applies a Gaussian (`radius_sigma_mm / resample_mm` = 1.5 samples, mode nearest) to its radii in `centerline._resample`, so the same filter is applied to the area-equivalent profile. Branches shorter than 1 mm keep inscribed radii. Runs on the final mask (after repair), before lumen refinement, lesions and solver.
- **Schema:** `V2Out.radius_mode: str = "inscribed"` added (optional field inside the optional `v2` block; default only so old files still load); `v2.timings_s` gets an extra key `radius`. No v1 field, route, status or error string changed.
- **stenosis_errors window rule:** nearest g_pred point to the GT lesion minimum, match <= 2 mm; window = pred points within +-2 mm arc length of the matched point; ds_pred = max over the window of 1 - r/r_ref with `reference_radius` of the pred branch. **GT side uses the same window rule** (deviation from the task text): with `ds_gt = Lesion.ds` the identity test `stenosis_errors(g, g)` gave +4.8 pp on the stenosis phantom because r_ref varies along the lesion and the window maximum is not at the radius minimum. So `ds_gt` = window max of ds on the GT branch around its lesion minimum, `rmin_gt` = radius at that point, and the v1 values are kept as extra columns `ds_lesion`, `rmin_lesion`. Bins use the windowed `ds_gt`. SPEC §13b updated accordingly. Lesions are those of v1 `detect_lesions` on `g_gt.trees` (not fragments), as in `stenosis_metrics`.
- **Test deviation:** on the elliptical tube (semi-axes 1.5 / 0.75 mm, 0.35 mm voxels) the v1 inscribed radius is about 0.99 mm, not 0.75 +- 0.15: the EDT of voxel centres is biased high by up to a voxel on a thin tube. The test asserts 0.75 <= inscribed <= 1.05 and area_eq = sqrt(1.5*0.75) +- 0.1.
- **eval_v2b setup:** non-repair rows use `V2Options(anatomy=False, flow_mode="diameter_law")` (no TotalSegmentator, v1-equivalent flow, so inscribed rows equal v1 results); repair rows use `V2Options(repair=True, lumen=...)` with anatomy on and flow `auto`, learned decider, as in S16. GT lesions are detected on the GT graph in the same radius_mode (`build_graph(GT)`, plus `area_eq_radii` on its trees for area_eq). gt_blur0.5 = `diag_v2b.blurred(gt, 0.5)`. Part files in `/data/v2/eval_b/parts/`, run as 3 shards; a case with zero GT lesions has no lesion rows (n_lesions_gt in the cases CSV); a failed row gets one lesion row with the error.

## D-V2-S22 — area_eq junction exclusion (2026-10-27)
`area_eq_radii(..., exclude_junctions=False)`: a slice is excluded if its arc-length distance to a junction is < 1.5 × local inscribed radius + 1.0 mm; junction = branch start when the branch has a parent, branch end when it has children (root start and terminal ends are not junctions). Local inscribed radius = the branch's v1 radius interpolated at the slice. Excluded slices get r by linear interpolation from the kept slices (clamped at the ends); if none is kept the inscribed profile is used. Smoothing as before, after the interpolation. Default off, `radius_mode` default untouched. Result (50 v2_train cases, GT masks): lesions inscribed 170 (13 severe), area_eq 389 (0 severe), area_eq_fixed 162 (6 severe, 0.46 × inscribed): the fix removes the inflation (0.95 × inscribed in total) but misses the severe-count criterion (0.46 < 0.50), so it is NOT adopted. Not used by H3.

## D-V2-S23 — lumen v3 training and frozen inference settings (2026-10-27)
- **Training** (`train/train_lumen_v3.py`, seeds 0/1/2, 30 000 steps, batch 4, none killed, ~0.57 h each): 50 % lesion windows (moderate+ slice 50 % / mild 50 %), per-slice loss weights 1/3/6, jit-only stratified validation, selection = moderate+ r_ins. Seed 2 deployed as `lumen_v3` (0.408 mm vs 0.453 mm for the old model on the same validation; small gain, moderate+ n = 368 slices).
- **refine_radii semantics:** the old code's "no centre component keeps v1" really means "no predicted pixel at all" (`center_component` falls back to the nearest component). Default `fallback="v1"` keeps exactly that. `nearest` accepts an off-centre component only within 1.0 mm of the centre; `interp` accepts only components containing the centre pixel and interpolates linearly between them (v1 beyond the first/last). `fallback_fraction` = slices whose centre pixel is not in a predicted component. `refine_radii` got an extra `stats` dict argument; `V2Out.lumen_fallback_fraction` (optional, None when lumen is off) carries it into result.json.
- **Freeze** (`scripts/freeze_lumen_v3.py`): validation cases = v2_train ids with id % 10 == 3 (85 cases; they have no first-pass masks, so GT centerlines shifted 0.5 mm per the S18 rule). Error = |refined radius − GT-graph radius| at GT lesion minima (v1 `detect_lesions`, inscribed graph), selection over moderate+ (ds ≥ 0.5; n = 77). Full grid in `reports/v3_lumen_freeze_grid.csv`. ## D-V2-S25 — extra synthetic decider rows for add / stop / extend (2026-10-27)
- **Why:** decider_synth has only 171 `add` and 568 `stop` rows (36 760 total); real rows have 8 `add`, 131 `extend`, 0 `stop` (`label_real` never emits `stop`). - **Change:** `DamageParams` gets `thin_bias_prob: float = 0.0` and `thin_max_radius_mm: float = 1.3`. A first trial that filtered on the branch *median* radius did not move the extend rows (median r_local still 1.45 mm: cuts 30–80 % along a tapering branch are thicker than its median), hence the check at the cut point. ## D-V2-S26 — cross-fit segmenter runs to harvest real segmentation failures (2026-10-27)
- **Why:** real failure rows are scarce (73 `v2_realfail` cases) and fine-tuning can only use them through cross-validation. Segmenters trained on part of `v2_train` and run on the rest give realistic out-of-sample errors for all 640 `v2_train` cases, for both the decider (`label_real`) and the gap-filler (prediction as damaged mask, GT as target).
- **Setup:** `Dataset511_ImageCASxfit` (`scripts/xfit_setup.py`) = symlinks to Dataset501 files of `v2_train` cases only (640; test, `v2_holdout`, `v2_realfail` are not even linked), its own `nnUNetPlans.json` (`dataset_name` changed, needed because nnU-Net reads the data folder from the plans) and a 3-fold `splits_final.json` (ids shuffled with seed 0; val sizes 214/213/213). Dataset501 and its splits (which define the v2 roles) are untouched.
- **Runs** (`scripts/xfit_run.py`, container `twinloop-v2-xfit`): folds 0, 1, 2 in sequence, `nnUNetTrainer_100epochs` (not the full 1000: about 1/10 of the compute, and weaker, more failure-prone masks are wanted). The three runs differ in training data and in random init (nnU-Net does not expose a seed). A watcher copies nnU-Net's epoch-50 `checkpoint_latest.pth` to `checkpoint_ep50.pth`; `checkpoint_final.pth` is epoch 100. nnU-Net's `save_every` is 50, so there are 2 checkpoints per fold, not every 25 epochs as first proposed (a custom trainer would be needed for that). Each held-out third is predicted at ep50 and final (`--disable_tta`) into `/data/v2/xfit/pred/fold<k>_{ep50,final}/`.
- **Limits:** no real `stop` labels come out of this (`label_real` has no stop rule). Epoch-50 masks are noisier than anything the deployed first-pass model produces, so they should be tagged and checked before mixing into training. Timing: epoch ~104 s on a free GPU, so training ~3 h per fold, plus prediction; the GPU is shared with other jobs.
